# 全站流式加载与 Sonner 操作反馈设计

## 目标

改善 YlTt2025 在服务端数据请求和客户端异步操作期间的反馈：用户导航到公开页面或后台子页面时立即看到与目标页面结构一致的占位符；用户执行上传、定位、评论、资料和后台管理操作时能明确看到进行中、成功或失败状态。

## 现状与约束

- Next.js 16 App Router 页面主要使用 Server Components，公开内容和后台数据由服务端 Supabase 查询提供。
- 后台概览、用户、评论、审计及内容详情页面会等待服务端查询完成后才渲染主体。
- 公开首页、摄影、短片、故事及详情页同样存在服务端数据等待；详情页的评论请求还会在主体查询后继续等待。
- 项目已有 `components/ui/sonner.tsx` 封装和 `sonner` 依赖，但根布局尚未渲染 `Toaster`。
- 不能把整个应用改成客户端数据层，也不改变 Supabase 数据模型、鉴权边界或业务动作契约。

## 方案

### 1. 路由级流式占位符

在 App Router 路由段增加 `loading.tsx`，使用现有 `Skeleton`、表格和媒体块样式构造稳定尺寸的骨架：

- 根路由提供通用首屏兜底，覆盖登录、注册和无法由更深层 loading 覆盖的等待阶段。
- `(site)` 路由提供公开页面的标题、媒体网格和详情结构占位。
- `admin` 路由提供后台标题、统计块和表格占位；子页面沿用后台导航布局。
- 内容编辑详情沿用表单字段和编辑器区域的固定高度，避免切换时布局跳动。

这些文件只负责等待期间的渲染，不复制数据请求，也不改变页面的 Server Component 结构。

### 2. 细粒度 Suspense 流式传输

公开内容详情页先获取并渲染主体，再将评论查询放入独立的异步 Server Component，并用 `Suspense` 包裹。评论区在等待时显示评论表格骨架，主体内容不再被评论请求阻塞。鉴权用户上下文继续由现有服务端布局提供，评论交互保持客户端组件。

### 3. 全局 Sonner

在根布局挂载现有 `Toaster`，统一设置中文应用的右上角通知位置、可关闭按钮和现有主题变量。通知组件只挂载一次，避免在页面切换时重复创建。

### 4. 客户端异步操作反馈

按操作类型提供一致的 pending、success、error 反馈：

- 资料保存和头像上传：保留表单禁用与按钮文案，使用 toast 报告成功/失败。
- 评论发布、编辑、删除：使用 pending 状态禁用对应控件，并对成功/失败使用 toast；刷新后的评论列表仍由 `router.refresh()` 获取。
- 后台角色调整、评论显示状态调整：使用 action state 的结果触发 toast，保留可访问的错误文本。
- 内容媒体上传、EXIF 读取和反向地理编码：使用 loading/success/error toast 或状态提示，错误仍保留在表单上下文。
- 登录、注册和 GitHub 登录失败：保留现有表单错误，并补充 toast；成功重定向仍由 Server Action 负责。
- 成功后直接重定向且没有 action state 的操作（例如删除内容、退出登录）：至少提供提交中的按钮状态；不为无法可靠关联生命周期的请求伪造成功 toast。

### 5. 可访问性与稳定布局

- 所有骨架区域使用 `aria-busy` 或合适的状态文本，表格和媒体占位符维持目标内容的尺寸。
- Toast 不替代表单内错误文本；错误信息仍放在触发操作附近并带有 `role="alert"` 或 `aria-live`。
- 仅在真实异步操作期间禁用控件，避免阻塞无关导航。

## 验证

- 运行 TypeScript 检查和现有 Vitest 测试。
- 启动 Next.js 开发服务器，验证公开首页、详情页、后台子页面导航时出现骨架且无空白页。
- 验证评论区、资料保存、后台角色/评论状态操作的 Sonner 成功与失败反馈。
- 验证桌面和移动视口下骨架不溢出、不造成明显布局跳动，并检查浏览器控制台无新增错误。

## 不在本次范围

- 将公开数据改造成 SWR/React Query 客户端数据层。
- 修改 Supabase schema、RLS、鉴权策略或业务数据查询语义。
- 新增独立的全局 API 错误上报系统。
